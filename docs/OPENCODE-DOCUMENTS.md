# План для OpenCode: документы вуза в карточке (с 07.10.2026)

Кто читает: агент в OpenCode. Сначала `README.md`, `docs/HANDOFF.md` (только нужные разделы) и `docs/OPENCODE-PLAN.md` (жёсткие правила оттуда действуют и здесь).

## Что нужно

В карточке программы — блок **«Документы»**: что вуз просит приложить к заявке (аттестат, перевод, паспорт, рекомендации, эссе, справка о доходах, сертификат языка и т. п.). Это **не вопросы анкеты** и на вердикт не влияет: человек видит список и понимает, что готовить.

## Жёсткие правила

1. **Ничего по памяти.** Каждый пункт — дословная цитата из снимка в `raw/<id>/…`. Страница не называет документы — поле `null`, а не «типичный список».
2. Цитату проверяет `python -m tools.reverify`: она должна дословно встречаться в тексте снимка.
3. Страница про другой путь (аспирантура, обмен, граждане ЕС) — не брать. Смотри заголовок над цитатой: бакалавриат, иностранцы, нужный цикл.
4. Документ «на выбор» (одно из двух) пиши как есть, одной строкой: «аттестат или справка о завершении школы».
5. Не придумывать сроки действия, заверку, апостиль: только если они прямо названы на странице.
6. Остальное — по `docs/OPENCODE-PLAN.md`: тесты зелёные, `git add` по явным путям, один вуз — один коммит, force push запрещён.

## Данные

Самый маленький путь — **не новое поле, а новый тип условия**. В `tools/schema.py` в `CONDITION_KINDS` добавить `"documents"`. Запись в `textConditions` остаётся прежней:

```json
{"ru": "Нужен аттестат с оценками, переведённый на английский.", "evidence": "<дословная цитата из raw/>", "field": null, "kind": "documents"}
```

Один документ — одно условие (так карточка покажет список, а не абзац). Если у типа «documents» нет `field`, проверь, что `TAGS_REQUIRED` допускает `field: null` (у `note` так же); иначе используй существующее поле программы.

Почему так, а не отдельный `documents: [...]`: `tools.build`, `tools.reverify`, `tools.review` и файл `data/conditions/<id>.json` уже умеют условия с цитатами. Отдельное поле пришлось бы учить всему этому заново.

## Интерфейс

- `js/card-model.js`: рядом с `must`, `money`, `steps` (строки ~97–100) добавить `const documents = take((c) => c.kind === 'documents');` и раздел `{ key: 'documents', title: 'Документы', items: documents }` в `sections` — **до** «Что ещё потребуется», чтобы документы не терялись среди условий.
- `js/render.js`: раздел рисуется тем же кодом, что остальные `sections`. Новой вёрстки не нужно; если список длиннее 6 пунктов, пусть сворачивается, как остальные длинные разделы.
- `js/plan.js`: `TASK_KINDS = ['must', 'steps', 'money']` (стр. 181). Документы — это то, что человеку надо **собрать**, поэтому добавить `'documents'`, чтобы они попадали в «Мой план». Сначала проверь, что это не сломает тесты плана.
- Карточка без документов: раздел не показывать (не писать «документы не указаны» — это про отсутствие данных на странице, а не вуза).
- CSS: лимит `css/style.css` 44 КиБ, сейчас 44 169 байт из 45 056. Если нужен новый стиль — только то, чего нет; лучше не нужен.

## Очередь

Начать с вузов, которые Мурод чаще всего увидит у людей из Таджикистана и Центральной Азии: карточки со статусами «Подходишь» и «Проверь» при типичном профиле — 30–50 штук. Порядок: сначала те, у кого `coverage` полное или частичное (деньги), потом остальные.

1. Сначала только код (схема, `card-model`, `plan`, тесты) — один коммит, **без данных**. Показать Муроду на одной карточке (`utwente`).
2. Потом данные по одному вузу: `python -m tools.look <id> documents`, `... "required documents"`, `... аттестат`, цитаты, `reverify`, `review --by-assistant`, `build`, коммит.
3. Страница не читается или документы не названы — вуз пропустить, записать в «Не добавлены» с причиной.
4. После первой сессии (15 программ) — коротко отчитаться Муроду и ждать следующей порции.
5. **Остальные программы (все 323).** Когда первые 30–50 приняты, идти дальше по тому же конвейеру, по одной программе в сессию. Порядок: страны из приоритетов Мурода (Центральная Азия, Турция, Россия, Корея, Япония, Китай, Германия), потом остальные. Список считать так: `ls data/programs`, вычесть уже сделанные (где в `data/conditions/<id>.json` есть `"kind":"documents"`). Страновые программы и госстипендии (`kind` не «university») — документы у них общие по программе, а не по вузу: брать с официальной страницы программы.
6. Конец работы: отчёт «сколько программ с документами, сколько без и почему (страница не называет, скан PDF, не открывается)».

## Не делать

- Не добавлять документы вопросами в анкету.
- Не добавлять «общий список документов» для страны или типа вуза.
- Не менять вердикт из-за документов.

## Режим работы: 15 программ за сессию, агентами, быстро (решение Мурода 07.10.2026)

Мурод даёт тебе **по 15 программ на сессию** (список id). Твоя задача — закончить их **как можно быстрее** и сразу отправить. Не задавай вопросов, не жди подтверждений между шагами.

1. **Запусти максимум подагентов (`task`, тип `general`) — по одному на программу, все 15 сразу, одним сообщением.** Не по очереди.
2. Каждый подагент делает только то, что не пересекается с остальными:
   - `python -m tools.fetch <id>` (снимок в `raw/<id>/`, у каждой программы свой);
   - ищет документы через `python -m tools.look <id> <слово>`;
   - пишет **только** `proposed/<id>.documents.json` — список `{ru, evidence}` с дословными цитатами, или `null`, если страница документы не называет;
   - в `data/`, `changelog.json`, `tools/` и git **не лезет**.
   Верни одну строку: `id — N документов / null / не читается (причина)`.
3. **Сам (не подагенты) собираешь результат — последовательно,** потому что `build` и `data/changelog.json` общие:
   - по каждому `proposed/<id>.documents.json` внеси условия `kind: "documents"` в `data/programs/<id>.json`;
   - `python -m tools.reverify <id>` (цитаты на месте), `python -m tools.review <id> --by-assistant`;
   - один `python -m tools.build` на всю порцию, один прогон тестов (`node --test` и `PYTHONUTF8=1 python -m unittest discover -s tools/tests -t .`).
4. **Коммиты — по одной программе** (`git add` только явные пути этой программы), сообщение по-русски. Пуш — один раз в конце порции: `git fetch && git rebase origin/main`, потом пуш. Рвётся — порциями по ~5 коммитов с повтором.
5. Программа, которую агент не смог прочитать за 10 минут, — в «Не добавлены» с причиной, остальные не задерживает.
6. В конце — отчёт одной таблицей: id, сколько документов, пропущено/почему, хэш коммита. Затем остановись и жди следующие 15.

Первая порция (код без данных, шаг 1 выше) идёт без подагентов.

## Команда «делай 15 по плану»

Мурод пишет только это. Всё остальное — твоё:

1. Прочитай этот файл и `docs/DOCUMENTS-PROGRESS.md` (там «Сделано» и «Пропущено»).
2. Если код ещё не сделан (в `CONDITION_KINDS` нет `documents`) — сделай шаг 1 из «Очереди» (код и тесты, без данных), коммит, покажи на `utwente` и остановись. Это единственный случай, когда ты ждёшь ответа.
3. Иначе возьми **следующие 15 программ**, которых нет ни в «Сделано», ни в «Пропущено». Порядок — из «Очереди» (сначала 30–50 для таджикского профиля, потом страны из приоритетов, потом остальные). Список не спрашивай, выбери сам.
4. Выполни по разделу «Режим работы» (агенты, сборка, коммиты, пуш).
5. **После пуша** перенеси эти 15 id в `docs/DOCUMENTS-PROGRESS.md`: сделанные — в «Сделано», пропущенные — в «Пропущено» с причиной. Коммит `docs/DOCUMENTS-PROGRESS.md` отдельным коммитом, пуш.
6. Ответь Муроду таблицей и строкой «осталось N программ». Остановись.

Когда «осталось 0» — напиши «все программы пройдены» и не бери новые.
