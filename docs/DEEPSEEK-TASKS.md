## Общие правила (вставлять в начало каждой задачи)

```
Ты работаешь в репозитории Nerio. Сначала прочитай AGENTS.md целиком, он главнее этого текста.

Рабочее место:
- Отдельный worktree и ветка deepseek/<задача>-<дата> от свежего origin/main.
  Перед стартом: git fetch, ветка от origin/main.
- В main не вливать, на Vercel не выкладывать, PR не открывать без слова Мурода.
- Вывод сборки не коммитить (data/index.json, data/details.json, data/route.json,
  data/conditions/, feed.xml, sitemap.xml, programs/): после python -m tools.build
  вернуть их git checkout. Пересобирает Claude при вливании.
- Менять только свои файлы из docs/WORK-SPLIT.md.

Данные:
- Каждый факт — с дословной цитатой из снимка страницы в raw/<id>/<дата>/
  и ссылкой на официальный источник (сайт вуза, правительства, фонда).
  Блоги, агентства и форумы — не источник.
- Новый снимок сохранять тем же способом, что и прежние (tools/fetch.py, tools/snapshot.py).
- Не уверен — поле не заполняй, причину запиши в отчёт. Пустое лучше выдуманного.
- Новые домены источников не подключать: собери список с причинами, Мурод даст «да».
- raw/ целиком не открывать: python -m tools.look <id> <слово> или grep.

Код:
- Пиши только то, что нужно задаче. Не рефакторить рядом, не добавлять зависимости,
  не менять схему и валидатор — если мешают, напиши в отчёт.
- Перед каждым коммитом зелёные:
    node --test
    PYTHONUTF8=1 python -m unittest discover -s tools/tests -t .
    python -m tools.build
  плюс проверка задачи (указана ниже).

Отчёт:
- docs/REPORT-<дата>-<задача>.md: что сделано (числа), что пропущено и почему
  (по строке на программу), какие домены ждут «да», какие команды прогнаны
  и с каким результатом.
- По-русски, коротко, без «успешно», «качественно» и прочих оценок. Только проверенное.
- AGENTS.md не трогать: строку статуса впишет Claude при вливании.
```

Ponytail (github.com/DietrichGebert/ponytail) — это правила «пиши меньше кода» для агента, сайты он не обходит. Его суть уже в разделе «Код» выше. Если хочешь подключить его как плагин к DeepSeek или Codex, скажи: Claude прочитает его хуки перед установкой.

## DS-1. Материалы заявки по программам

**Зачем:** без этого Nerio не скажет ученику, что готовить. Это главная задача списка.

**Готово для старта:** схема `docs/MATERIALS-SCHEMA.md`, валидатор `tools/materials.py`, тесты `tools/tests/test_materials.py` (тест по репозиторию проверяет все файлы `data/materials/`, CI покраснеет на неверном файле).

```
Задача DS-1, партия <N>: программы <список id>.

Для каждой программы найди на официальных страницах, какие материалы ученик пишет,
собирает или просит у людей: эссе (с дословными вопросами и лимитами), рекомендации
(сколько, от кого), список активностей, CV, награды с подтверждением, портфолио работ,
учебный план, видео, собеседование, сертификаты достижений.
Запиши data/materials/<id>.json строго по docs/MATERIALS-SCHEMA.md.

Начни со снимков, которые уже есть в raw/<id>/ (tools.look), и с полей, которые
частично есть: data/interview.json (собеседование), textConditions программы,
recommenders в js/recommenders.js. Не копируй их — сверяй с цитатой.
Если в снимках нет страницы с требованиями к заявке (application guide, required
documents, how to apply), скачай её с того же официального домена.

Проверка задачи: python -m tools.materials --check (каждая цитата найдена в снимке).
В отчёте таблица: id | найдено типов | notStated | пропуск и причина.
```

**Партии:** по 30 программ. Сначала программы с открытым приёмом и самым близким сроком (`deadline.closes` впереди), внутри — по странам, чтобы похожие формы шли подряд. Список партий Claude даёт по мере приёмки.

**Приёмка Claude:** выборочно 5 программ из партии сверяю с источником глазами, плюс механическая проверка цитат. Если в выборке больше одной ошибки — партия возвращается.

## DS-10. Цитаты, которых нет в снимках

**Зачем:** `python -m tools.validate` должен быть зелёным, иначе он ничего не ловит. 25.11 Claude переснял 12 программ, 4 прошли; у 11 записей 40 цитат не совпадают с текущими страницами. Рабочий список с ближайшим текстом свежего снимка: `docs/QUOTE-FIXES-2026-11-25.md`. Ветка от `origin/claude/quote-fixes` (там свежие снимки).

```
Задача DS-10. Для каждой цитаты из docs/QUOTE-FIXES-2026-11-25.md найди в свежем снимке
raw/<id>/2026-11-25/ (у cornell, vanderbilt, vassar — тоже 2026-11-25) текущий текст об этом же:
- смысл тот же, слова другие → evidence заменить дословным текстом страницы; ru не трогать;
- факт другой (число, дата, балл) → evidence и ru по новому тексту, структурное значение
  (минимумы экзаменов, суммы) по новому тексту; каждую такую правку — строкой «было → стало»;
- текста больше нет → условие textConditions удалить; поле eligibility не трогать, только в отчёт;
- страница не отдаёт текст (JS, заглушка) → не трогать, в отчёт.
Поле deadline не менять: сроки ждут решения Мурода (очередь DS-5).
Цитату не выдумывать и не собирать из кусков разных мест страницы.
Проверка задачи: python -m tools.validate без ошибок по 11 программам или каждая оставшаяся —
в отчёте с причиной; после правок python -m tools.reverify <id> --write только для прошедших.
```
