## 1. Задача A — статус заявки по цели

Статусы: `thinking` «Рассматриваю» (по умолчанию, в хранилище не пишется), `preparing` «Готовлю документы»,
`submitted` «Подал заявку», `answered` «Получил ответ». Дата `since` ставится при смене статуса.
Статус ставит только человек: подачу на сайте вуза мы не видим, сами ничего не отмечаем.

Сделать:
1. `index.html`: `<link rel="modulepreload" href="js/goal-status.js">` рядом с остальными.
2. Тесты `tests/goal-status.test.js`: `statusOf` по умолчанию; `isSent`; `goalProgress` (общее дело считается у
   каждой программы, сортировка по сроку, потом по порядку); `progressLine` во всех ветках (подана, ответ, нет дел,
   всё отмечено, «и ещё N»).
3. Тесты route-state: `normalize` отбрасывает чужой статус, плохой id, плохую дату; `setGoalStatus` не сдвигает дату
   при том же статусе, `thinking` удаляет запись; экспорт/импорт сохраняет `statuses`; `clearProgress` статусы не
   трогает (проверь, как сейчас, при необходимости поправь).
4. «Сегодня» (`js/today-view.js`):
   - `todayModel` принимает `routeState`; цели со статусом `submitted`/`answered` не попадают в `open`
     (обратный отсчёт «До подачи в …» и список дат): срок подачи по ним уже не актуален.
   - Новый блок «Заявки» в `renderToday` (после `dates`): по строке на цель — имя, статус, `progressLine`.
     Если все цели «Рассматриваю», блок не показывать (экран и так плотный).
   - В `renderRouteView` (main.js) `routeState` уже передаётся; проверь, что `todayModel` его получает.
   - Тест в `tests/today.test.js`: поданная цель исключается из отсчёта; без статусов поведение прежнее.
5. Удалить из `route-view.js` мёртвый код после переноса, если остался.

Приёмка: смена статуса на «Мой путь» сохраняется после перезагрузки; на «Сегодня» отсчёт идёт до следующей
неподанной цели; фокус после смены остаётся на том же селекте; экспорт/импорт пути переносит статусы.

## 3. Задача C — фильтры в «Куда можно»

Сначала проверь покрытие данных и запиши числа в итог (не обещай того, чего данные не дают):
1. Взнос за подачу: `feeOf` / `feeCell` в `js/cost.js`. Сколько из программ каталога имеют известный взнос (в
   `index.json` или только в `details`, которые грузятся лениво)? Если взнос известен лишь после загрузки условий,
   то фильтр «Без взноса» либо работает только по загруженным карточкам (тогда подпись об этом обязательна), либо
   взнос надо вынести в `index.json` через сборку (`python -m tools.build`, схема до кода — правило из AGENTS.md).
   Выбери второе, если взнос есть у большинства; иначе фильтр не добавлять и написать почему.
2. Duolingo: трек `data/prep/exams/duolingo.json`; слово «Duolingo» встречается в 213 файлах данных. Найди поле,
   в котором программа называет принимаемые английские экзамены, и считай «принимают» только по нему, не по
   упоминанию в тексте.

Если покрытие достаточное:
- `js/filter.js`: `matchesFilter(item, {…, noFee, duolingo})`, `bucketCounts` учитывает их; чистая функция,
  тесты в `tests/filter.test.js`.
- `js/render.js`: `data-fee-free` и `data-duolingo` на карточке; `index.html` — два переключателя в `#catalog-tools`
  с подписями «Без взноса за подачу» и «Принимают Duolingo».
- Правило честности: «без взноса» только когда источник прямо называет 0 или отмену взноса; «неизвестно» не равно
  «нет». Подпись у фильтра: «Показываем только программы, где это указано в источнике».
