# Понятная и полезная выдача — дизайн

Дата: 14 сентября 2026. Утверждено человеком в чате: разметка всех условий,
сводка сверху с группами свёрнутых карточек, анкета сворачивается.

## Зачем

Человек заполнил анкету как таджикский выпускник (11 лет школы, выпуск 2027,
балл 4.8, IELTS не сдан) и не смог пользоваться результатом. Замеры на этом
профиле, 50 карточек:

- страница высотой 58 649 px, в среднем 2 668 символов на карточку, всё
  раскрыто сразу; одна карточка Гарварда не помещается в экран телефона;
- 40 жёлтых, 8 зелёных, 2 красных — цвет ничего не различает;
- самая частая причина (14 раз): «Требование к языку есть, но инструмент его
  не считает — читай условия ниже», а ниже 9–19 условий без указания, какое
  из них нужное;
- обходные пути в данных есть, но не связаны с отказом: у APU условие
  «Другие пути для 11-летней школы: IB, A-level, индивидуальная проверка»
  лежит в общем списке, а отказ «нужно 12 лет школы» стоит отдельно;
- даты в виде `2027-01-01`; анкета на телефоне занимает 1 105 px до
  первого результата.

Цель: ответ, который объясняет и подсказывает. Не «нельзя», а «пока нельзя,
потому что нужно X; обойти можно через Y» — и всё длинное спрятано, пока
человек сам не откроет.

## Что не меняется

- Логика правил: какие профили получают pass/fail/unknown. Меняется только
  то, что правило возвращает вместо текста (см. «Коды причин»).
- Правило «данные только из источника». Интерфейс не придумывает обходных
  путей: показывает только условия, размеченные как обходной путь.
- Стек: статичный сайт без сборки, ES-модули, системные шрифты, никаких
  фреймворков. Профиль только в localStorage.
- Порядок «сначала куда можно».

## Не входит

Подпороги IELTS по частям, новые страны в анкете, перевод на таджикский,
сводка по обязательным документам («CSS Profile нужен в 9 программах» —
свободный текст так не агрегируется).

## 1. Разметка условий

Каждое условие в `textConditions` получает два поля:

```json
{ "ru": "…", "evidence": "…", "field": "schoolYears", "kind": "workaround" }
```

`field` — к какому требованию анкеты относится условие: одно из
`citizenship`, `schoolCountry`, `schoolYears`, `graduationYear`, `age`,
`gpa`, `language` — или `null`, если ни к какому.

`kind` — что человеку с этим условием делать:

| kind | Значит | Пример |
|---|---|---|
| `workaround` | другой способ выполнить или обойти требование из `field` | «Другие пути для 11-летней школы: IB, A-level…» |
| `must` | обязательное требование сверх анкеты | «Нужен SAT или ACT», «Выдвижение школой» |
| `money` | что покрывается, сколько платить, риски потерять деньги | «Скидка 30–100%, взнос за общежитие платишь сам» |
| `steps` | как подавать: документы, этапы, сроки, платформа | «Подают через Common App до 1 ноября» |
| `note` | всё остальное: контекст, предупреждения | «Мест для иностранцев 444» |

Правила разметки:

- `ru` и `evidence` не меняются. Разметка — только два новых поля.
- `workaround` требует непустого `field`. Ставится, только если текст прямо
  описывает иной путь к тому же требованию. «Подумай о foundation-году» без
  слов программы об этом — не `workaround`. Ложный обходной путь — худшая
  ошибка разметки: карточка пообещает то, чего нет.
- Одно условие — один `kind`. Если текст смешивает два, выбирается то, что
  человек будет с ним делать, а сомнение записывается в отчёт разметчика.
- `field` ставится и у `must`/`note`, если условие уточняет требование анкеты
  («Таджикистан в категории C: нужно 90% успеваемости» → `gpa`, `note`).

Валидатор (`tools/validate.py`) проверяет: `field` из списка или `null`,
`kind` из списка, у `workaround` есть `field`. Пока разметка не закончена,
поля необязательны. Последняя задача разметки включает их обязательность.

Разметку делают агенты через `tools/review.py --by-assistant`, по 7–8 карточек
на агента, затем круги ревью без контекста, пока последний не найдёт ничего.
Проверка после каждого круга: в диффе меняются только `field`/`kind`,
`source.lastVerified` не меняется ни у одной карточки.

## 2. Данные для сайта: два файла

Всё нужное в одном `data/index.json` весит 66,6 КБ по проводу при пределе
64 КБ (замер на 50 карточках с разметкой, описанием покрытия, ссылкой на
подачу и источником). Поэтому индекс делится.

**`data/index.json`** — всё для ответа, сводки и свёрнутой карточки:
`id`, `name`, `hostCountry`, `level`, флаги `coverage`, `eligibility` (как
сейчас, без цитат), `deadline`, и новое поле `workaroundFields` — список
полей, у которых есть хотя бы одно условие `workaround`. Текстов условий в нём
нет. Предел 64 КБ сохраняется; индекс станет заметно легче, запас вырастет.

**`data/details.json`** — всё для раскрытой карточки, по `id`:

```json
{
  "generatedAt": "…",
  "programs": {
    "apu-japan": {
      "coverageNote": "Стипендия снижает только плату за обучение…",
      "applyUrl": "https://…",
      "source": { "url": "https://…", "lastVerified": "2026-09-13", "approvedBy": "assistant" },
      "textConditions": [{ "ru": "…", "field": "schoolYears", "kind": "workaround" }]
    }
  }
}
```

Цитаты в него не входят. Свой предел — 128 КБ по проводу. Формат записи тот же,
что у индекса: без отступов, программа на строку.

Сайт грузит индекс, рисует ответ, затем сразу в фоне грузит детали. Раскрытая
карточка до загрузки деталей показывает причины (они считаются из индекса) и
строку «Подробности загружаются…». При ошибке — «Подробности не загрузились.
Проверь интернет» с кнопкой «Попробовать ещё раз». Условия без разметки (до
окончания разметки) показываются одним списком «Условия программы», как сейчас.

## 3. Коды причин

Правила возвращают `{ status, code, params }` вместо `{ status, message }`.
`code` — строка вида `поле.состояние`, `params` — числа и списки для текста.
Текст собирает новый модуль `js/wording.js`. Так тексты правятся без правки
логики, а сводка считается из тех же кодов.

Общие состояния для каждого поля (`<f>` — имя поля):

| code | status | Когда |
|---|---|---|
| `<f>.missing-rule` | unknown | правило `null` |
| `<f>.by-institution` | unknown | `definedBy: institution` |
| `<f>.not-measured` | unknown | `notMeasured: true` |
| `<f>.no-value` | unknown | в профиле пусто |

Особые состояния:

| code | status | params |
|---|---|---|
| `citizenship.denied`, `schoolCountry.denied` | fail | — |
| `citizenship.not-in-list`, `schoolCountry.not-in-list` | fail | — |
| `schoolYears.below-min` | fail | `min`, `mine` |
| `graduationYear.too-early` | fail | `min`, `mine` |
| `graduationYear.cycle-unknown` | unknown | — |
| `graduationYear.after-cycle` | fail | `max`, `mine` |
| `graduationYear.too-late` | fail | `max`, `mine` |
| `age.asof-unknown` | unknown | — |
| `age.near-max` | unknown | `age`, `limit`, `why` |
| `age.over-max` | fail | `age`, `max` или `maxExclusive` |
| `age.near-min` | unknown | `age`, `min`, `why` |
| `age.under-min` | fail | `age`, `min` |
| `gpa.near-threshold` | unknown | `mine`, `need` (проценты) |
| `gpa.below-advisory` | unknown | `mine`, `need` |
| `gpa.below` | fail | `mine`, `need` |
| `language.score-missing` | unknown | `options`, `advisory` |
| `language.below-advisory` | unknown | `options` |
| `language.below` | fail | `options` |
| `language.other-test` | unknown | `tests`, `options`, `advisory` |
| `language.no-certificate` | unknown | `options`, `advisory` |

`why` для возраста — одно из `no-dates`, `cycle-guessed`, `asof-unknown`,
`unconfirmed` (сейчас это четыре готовые фразы в `checkAge`). `options` —
массив `{ test, min }` из `anyOf`.

`verdict.evaluate` возвращает те же `status`, `reasons` (теперь с кодами) и
`attested`. Цвет и порядок не меняются.

## 4. Как написаны ответы

### Правила голоса

1. Каждый ответ, кроме «можно», говорит три вещи: что не так, почему, что
   делать. Если сделать нечего — честно: «обходного пути программа не
   называет».
2. «Пока» там, где ситуацию можно изменить: сдать экзамен, указать поле,
   дождаться возраста. Без «пока» — где нельзя (гражданство).
3. Никаких слов о внутренностях: «инструмент», «не считает», «правило»,
   «поле», имена из кода, ISO-даты. Вместо «инструмент не считает —
   читай ниже»: «Программа описывает это требование словами» — и нужное
   условие сразу под этой строкой.
4. Сомнение остаётся сомнением: «это не отказ, но…». Уверенности не
   прибавляем.
5. На «ты», коротко, без канцелярита. Заголовок свёрнутой карточки — до
   80 символов.

### Функции модуля

`reasonText(reason)` → `{ title, detail, short, changeable }`:
- `title` — о чём причина: «Школа», «Английский», «Возраст»…
- `detail` — полное объяснение для раскрытой карточки;
- `short` — хвост заголовка свёрнутой карточки. У `unknown` — действие в
  инфинитиве («сдать английский…», «указать дату рождения»), у `fail` —
  констатация («нужно 12 лет школы, у тебя 11»);
- `changeable` — только у `fail`: может ли человек это изменить сам.
  `true` у `language.below`, `gpa.below`, `age.under-min`,
  `graduationYear.after-cycle`; у остальных `false` (гражданство, страна и
  годы школы, возраст сверху, выпуск раньше или позже закреплённого года).

`headline(verdict, program)` → строка свёрнутой карточки.

### Образцы (ориентир для всех кодов)

| code | short | detail |
|---|---|---|
| `schoolYears.below-min` | «нужно 12 лет школы, у тебя 11» | «Программа принимает после 12 лет школы, а у тебя 11.» |
| `schoolYears.not-measured` | «уточнить требование к школе» | «Программа описывает требование к школе словами. Вот что она пишет:» |
| `language.no-certificate` | «сдать английский (IELTS от 6.5)» | «Нужен сертификат: IELTS от 6.5, TOEFL от 90 по старой шкале или от 4.5 по новой, Duolingo от 125. Сертификата пока нет — сдать ещё успеешь.» |
| `language.no-certificate` + advisory | «сдать английский (желательно IELTS от 6.5)» | «Программа советует IELTS от 6.5, но это не порог — решает отбор. Сертификат всё равно понадобится.» |
| `language.below` | «результат экзамена ниже порога» | «Программе нужен IELTS от 6.5, твой результат ниже. Экзамен можно пересдать.» |
| `gpa.below-advisory` | «сверить балл с условиями программы» | «Твой балл — 88%, программа называет 90%. Это не отказ: число не жёсткий порог или к нему есть обходной путь.» |
| `age.over-max` | «к подаче тебе будет 21, берут младше 21» | «На дату приёма тебе будет 21, а программа берёт младше 21.» |
| `citizenship.denied` | «не принимает граждан твоей страны» | «Программа не принимает граждан твоей страны.» |
| `age.no-value` | «указать дату рождения» | «Укажи в анкете дату рождения — иначе не проверить, подходишь ли ты.» |
| `age.missing-rule` | «уточнить требования к возрасту» | «На страницах программы про возраст ничего не нашлось. Если сомневаешься, спроси у неё.» |
| `gpa.by-institution` | «узнать требование к баллу в вузе» | «Требование к баллу ставит принимающий вуз, у каждого своё. Смотри на сайте вуза, куда подаёшь.» |

Названия экзаменов: «IELTS», «TOEFL по старой шкале», «TOEFL по новой
шкале», «Duolingo». В `detail` перечисление через запятую с «или» перед
последним.

### Заголовок свёрнутой карточки

- `yes` → «Можно подавать».
- `no` → «Пока нельзя: {short}» при `changeable`, иначе «Нельзя: {short}» —
  по первой fail-причине. Плюс « · есть обходной путь», если поле этой
  причины в `workaroundFields`.
- `check` → «Можно, но сначала: {short первой причины}» (+ « и ещё N»).
  Порядок причин внутри: сначала то, что делает сам человек (`no-value`,
  `no-certificate`, `score-missing`, `other-test`), потом остальное.

## 5. Экран результатов

### Анкета

Обёрнута в `<details>`. В `<summary>` — строка профиля из
`profileSummary(profile)`: «Таджикистан · 11 лет школы · выпуск 2027 · балл
4.8 · IELTS не сдан». Если страна школы отличается от гражданства — после
гражданства «школа в России». Для пустого профиля: «Заполни анкету».

- При загрузке: открыта, если не заполнены гражданство, страна школы, годы
  или год выпуска; иначе закрыта.
- Внизу анкеты кнопка «Показать, куда можно подать» — закрывает анкету и
  прокручивает к сводке.
- Пока человек печатает, анкета сама не закрывается. Результаты под ней
  пересчитываются на лету, как сейчас.

### Сводка (`js/summary.js`, чистые функции)

До четырёх строк, в таком порядке, каждая — только если есть что сказать:

1. «Можешь подать в 8 программ. Ближайший срок — 9 октября, стипендия
   Пирсона.» Срок — ближайший `closes` среди `yes` с незакрытым приёмом. При
   нуле: «Прямо сейчас подать некуда — ниже видно, что поменять.»
2. Лестница экзамена: «Наберёшь IELTS 6.5 — можно будет подавать ещё в 12
   программ, 7 — ещё в 3.» Расчёт: экзамен — тот, что у человека отмечен
   (первый по порядку анкеты), иначе IELTS. Кандидаты — различные `min` этого
   экзамена в `anyOf` у программ не в `yes`, выше текущего балла человека,
   по возрастанию. Для каждого
   кандидата профиль копируется с этим баллом, считается, сколько программ
   станут `yes`, которые не были `yes` при предыдущем шаге. В текст идут до
   трёх шагов с приростом больше нуля.
3. Пропуски анкеты: «Укажи дату рождения — без неё не проверить 6 программ.»
   Считается по причинам `<f>.no-value`, берётся поле с наибольшим числом.
4. Главная преграда: «Число лет школы закрывает 2 программы, у 1 из них
   есть обходной путь.» Поле с наибольшим числом `fail`, если такие есть.

Под сводкой одна строка мелко: «Ответ — только про то, пустят ли подавать.
Отбор, эссе и документы решают отдельно.»

`aria-live="polite"` переносится с `#results` на сводку: перерисовка
пятидесяти карточек на каждое нажатие не должна зачитываться целиком.

### Группы

Три `<section>` с заголовком и числом: «Можно подавать (8)», «Можно, если
доделаешь или уточнишь (40)», «Сейчас нельзя (2)». Группа = `status`. Внутри —
порядок как в `sortRows` (по сроку), программы с закрытым приёмом — в конце
группы. Пустая группа не показывается.

### Свёрнутая карточка (`<details class="card …">`)

В `<summary>`, построчно:
1. Название программы (жирным).
2. Заголовок ответа (цвет по статусу).
3. Срок: `deadlineLine(program.deadline, today)` —
   - `open`/`due`: «Подать до 1 января 2027 · осталось 3 месяца»;
   - `upcoming`: «Приём с 10 января 2027, до 20 февраля»;
   - `closed`: «Приём закрыт 9 октября 2026» (+ «, обычно повторяется каждый
     год», если `recurring: annual`);
   - `unknown`: «Сроки программа не объявила»;
   - `confidence` не `confirmed`: добавить « (ожидаемая дата)».
4. Покрытие: `coverageLine(coverage)` — «Покрывает учёбу, жильё и перелёт»,
   «Покрывает учёбу; жильё и перелёт — за свой счёт», «Что покрывает — в
   подробностях» (все `null`).

Карточка с закрытым приёмом — приглушённая, как сейчас.

### Раскрытая карточка

Строится из `cardModel(row, details)` — чистой функции, которая возвращает
разделы; DOM только отрисовывает. Разделы по порядку, пустые не
показываются:

1. **Почему так** (кроме `yes`). Для каждой причины: `title` жирным и `detail`.
   Под ней связанные условия:
   - `kind: workaround` с тем же `field` — под подписью «Как обойти:»;
   - для `not-measured`, `by-institution`, `missing-rule` — условия `must` и
     `note` с тем же `field` под подписью «Что пишет программа:»;
   - для `fail` без условий `workaround`: «Обходного пути программа не
     называет. Если сомневаешься — напиши в приёмную комиссию.»
2. **Что ещё потребуется** — `must`, не показанные выше.
3. **Деньги** — `coverageNote` и `money`.
4. **Как подавать** — `steps` и ссылка-кнопка «Открыть сайт программы»
   (`applyUrl`, `target="_blank" rel="noopener"`).
5. **Ещё** — вложенный `<details>`: `note`, не показанные выше, и «Не
   ограничивает» из `notLimitedItems`.
6. Подвал мелко: «Проверено по сайту программы 13 сентября 2026» + «,
   проверял ассистент», если `approvedBy: assistant`; ссылка на
   `source.url`.

Каждое условие показывается один раз.

### Открытое остаётся открытым

Сейчас `renderResults` очищает контейнер на каждое нажатие — все раскрытые
карточки захлопнулись бы при правке анкеты. Рендер запоминает `id` раскрытых
карточек (и раскрытые «Ещё») до очистки и восстанавливает после.

### Даты и числа (`js/lib/format.js`)

- `formatDate('2027-01-01')` → «1 января 2027».
- `timeLeft(today, date)` → «сегодня последний день», «остался 1 день», «осталось
  5 дней», «осталось 2 недели» (от 14 до 60 дней — недели), «осталось 3
  месяца» (от 61 дня — месяцы, округление вниз, при остатке ≥ 15 дней
  «3,5 месяца»).
- `plural(n, 'программа', 'программы', 'программ')`.

## 7. Проверка

- Python: валидатор тегов (допустимые, недопустимые, `workaround` без поля,
  обязательность после разметки); `build` пишет оба файла, в индексе нет
  `ru`, `workaroundFields` верный, оба предела размера.
- JS: тесты правил переходят с текста на `code`/`params` — логика тестов та
  же. Новые тесты: у каждого кода есть непустые `title`/`detail`/`short`;
  ни один текст не содержит «инструмент», «не считает», `\d{4}-\d{2}-\d{2}`,
  имён полей; образцы из таблицы выше; `headline`; сводка и лестница на
  фикстурах; `cardModel` — связывание, отсутствие повторов, запасной список
  для неразмеченных условий; `format` — месяцы, падежи, границы недель и
  месяцев; `profileSummary`.

  свёрнутом виде; раскрытие карточки; правка анкеты не закрывает раскрытую

  строку с кнопкой повтора; вёрстка не разъезжается, горизонтальной
  прокрутки нет.
- После реализации — круги ревью без контекста, пока последний не найдёт
  проблем: ложные обещания в текстах, связывание условий, сохранение
  раскрытых, пограничные даты, пустые группы, профиль без полей.
